# 工具清单与界面路线

这份清单用于选工具，不代表当前电脑已经安装全部工具。**已安装工具用 shell 启动**：运行本技能 `scripts/launch-tool.ps1 -Name <工具名>`（或直接执行 `Tools/` 下对应程序），启动后再用 computer use 操作它打开后的界面。不要用 AX/GUI 双击工具箱卡片来启动工具；只有工具未安装、需要通过工具箱下载页安装时，才用 computer use 操作工具箱界面。不要猜程序路径或参数。

| 目的 | 优先工具/界面 | 重点记录 |
| --- | --- | --- |
| 硬件基本配置 | 唯一保留的 hardware 查询；硬件信息页 | CPU、主板、内存、显卡、磁盘、操作系统及采集时间 |
| 温度、功耗、频率与降频 | 优先 **HWMonitor**（AX 可读，先用 observe；失败再 GUI 截图）；需要 HWiNFO 专属传感器时再用 HWiNFO（用 GUI 截图）；需要时 AIDA64 传感器页 | 当前/最小/最大/平均值，采样时刻，CPU/GPU 温度、功耗、频率、负载和限频标志 |
| CPU、内存频率与通道 | CPU-Z 的 CPU/Memory/SPD 标签页 | 型号、通道、DRAM 实际时钟、时序、每插槽信息；DDR 有效速率不能直接当实际时钟 |
| 显卡与显存状态 | GPU-Z 的 Graphics Card/Sensors 标签页；HWMonitor | GPU、驱动、显存、负载、温度、热点、功耗、时钟及限频原因 |
| 磁盘健康 | CrystalDiskInfo；需要时 HD Tune 信息/健康页 | 磁盘型号、健康状态、温度、SMART 原始值及异常项，勿只依据一个百分比判断损坏 |
| CPU 性能对比 | 工具箱「性能测试」界面、CPU-Z Bench、Cinebench（以实际安装为准） | 测试名称/版本、单核/多核、耗时、分数、供电状态、后台负载；通过界面读取结果和对比平台 |
| GPU 基准/稳定性 | 工具箱性能测试、FurMark 图形界面 | 选择的 GPU、分辨率/API、分数/FPS、时长、监控曲线；基准与烤机不能混称 |
| 存储性能 | CrystalDiskMark、AS SSD Benchmark 图形界面 | 目标磁盘、测试文件大小、次数、读写指标；属于写盘测试，需要对应授权 |
| 蓝屏与系统异常 | BlueScreenView、工具箱对应工具、事件查看器/可靠性监视器 | 时间、停止代码、转储摘要、近期驱动/硬件改动；单个模块名不能直接认定故障来源 |
| 启动与后台占用 | 任务管理器、Process Explorer、Autoruns（以工具箱现有条目为准） | CPU/内存/磁盘占用、进程来源、启动项；先观察再决定是否停用 |
| 网络问题 | 工具箱网络相关页面、系统网络设置和已安装检测工具 | 连接状态、网关/DNS、丢包/延迟、代理、错误信息；不默认重置整个网络 |

## 监控流程

有温度、卡顿、掉帧、降频或稳定性问题时，优先用 HWMonitor 打开传感器界面并记录一次空闲基线，再根据症状收集至少两个带时间点的观察。HWMonitor 先用 AX observe 读取；读不到或超时才用 GUI 截图。HWiNFO 的传感器界面适配较差，直接用 GUI 截图。读取当前值与最大值，确认负载是否真的发生。GPU 低占用下的低频不能当作降频，传感器缺失不能当作零。

图形界面提供 CSV/报告导出时优先用软件自己的导出/日志功能，随后读取本轮新生成的文件并注明来源；不能复用旧报告冒充本轮数据。无需为了采样调用工具箱 sensors/disks/cpuz 接口。

需要基准测试或性能平台对比时，通过工具箱界面进入，读取可见评分、测试条件和对比结果。不要调用平台的隐藏/内部 HTTP API。网络平台不可用时保留本地结果、注明缺少对比，不把网络错误解释成硬件故障。

## 测试与修复

已有明确测试授权时按授权范围执行，不重复询问。否则先用 question 卡片说明测试目的、预计时长、负载或写入范围。开始前在 GUI 设置有限时长和停止条件；无法设置自动结束时不要开启无人看守的高负载测试。监控异常或用户要求停止时，通过界面停止本轮测试，不关闭整个工具箱或无关程序。

修改设置前记录当前值，选择与证据最相关、可回退的一项，修改后用同样条件复测。不要把一组无关的“优化”一次性应用到电脑。
