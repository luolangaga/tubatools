# 电脑问题诊断与修复

先了解症状、发生条件和近期变化。只将 `hardware` 用作工具箱的直接查询接口；温度、SMART、CPU-Z、工具启动、跑分、平台查询等不再走工具箱业务 API 或旧 CLI。

## 观察并使用真实软件

1. 加载 `tuba-computer-use` 技能。先用 `AX` 的 `apps`/`observe` 查看工具箱和当前桌面；需要像素、拖动或 AX 读不到时再用 `GUI` 截图。控制提示未显示或用户点击停止时，不得继续控制。
2. 需要基本配置时运行本技能的 `scripts/hardware.ps1`。检查 `ok`、错误和采集时间；没有数据就明确说明，不能编造。该脚本只支持硬件信息，不要求安装 Node.js。
3. 按[工具清单与界面路线](references/gui-tools.md)选择工具。已安装工具用 shell 启动：`powershell -ExecutionPolicy Bypass -File .opencode/skills/tuba-toolbox/scripts/launch-tool.ps1 -Name HWMonitor`；启动后用 computer use 操作它打开的界面。不要用 AX/GUI 双击工具箱卡片来启动工具。工具未安装时，才通过工具箱搜索/分类页安装。
4. 与温度、功耗、降频、掉帧有关时，优先打开 **HWMonitor** 读取当前/最小/最大值及限频标志。HWMonitor 的界面已可被 AX 读取（用户实测）；先用 `AX observe` 读控件值，读取失败或超时才改用 `GUI` 截图。HWiNFO 的传感器窗口适配较差，优先用 `GUI` 截图读数值，不要反复点击它的表格。保留观察时间和负载条件；需要趋势时通过软件自己的日志/导出功能获取专业记录。
5. 需要性能评估时，从工具箱的性能测试界面进入，读取本地成绩和可见的平台对比。平台不通就说明缺少对比，继续使用可靠的本地证据；不调用不稳定的内部接口。
6. 根据实际观测给出证据、可能原因和下一步。修改后用相同条件验证结果；未验证不能说修复完成。

## 授权和可复用功能

正常导航、打开工具和只读观察可直接进行。高负载、写盘或系统修改沿用用户已明确给出的授权；不足时通过原生 question 卡片说明具体动作和范围。不要自动清理文件、禁用安全组件或进行无关“优化”。

如果某个方案适合重复使用并做成插件，先用 question 卡片询问「是否将此方案封装为插件」，提供「封装为插件」和「仅处理这次问题」。用户同意后加载 tuba-plugin 技能；拒绝/跳过则继续维护，不创建插件。内置工具入口珍贵：同一插件默认用一个多功能工具页面，不拆成多个简单入口。
